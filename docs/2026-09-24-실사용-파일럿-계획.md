# FlowDesk 실사용 파일럿 계획

## 목표

본인 업무에서 기존 ERP와 병행해 한 달치 실제 업무를 FlowDesk로 처리하고, 안정화된 흐름을 특정 고객사 납품용 기준으로 확정한다.

## 범위

### 1. 초기 데이터

기존 ERP에서 내보낸 파일을 원본으로 보존하고, 다음 master부터 가져온다.

- 품목: 코드, 품목명, 규격, 단위, 매입단가, 판매단가, 최소재고
- 거래처/공급처: 코드, 명칭, 담당자, 연락처, 주소
- 창고: 코드, 명칭
- 부서/사원: 코드, 명칭, 소속 및 활성 상태

원본 데이터는 Production DB에 직접 적재하지 않고, 먼저 격리 PostgreSQL에서 형식·중복·참조 무결성을 검증한다.

### 2. 실제 업무 흐름

- 구매요청 또는 구매 입력
- 입고 처리 및 재고 확인
- 견적 입력
- 판매계획 전환
- 출하 또는 재고조정
- 월말 잔량·금액 조회

각 단계는 저장 후 새로고침/API 재조회로 read-back하고, 입력 원본과 결과를 대조한다.

### 3. 성공 기준

- 실제 업무 1개월분의 핵심 문서를 누락 없이 입력
- 구매→입고→재고 잔량이 기존 ERP와 일치
- 견적→판매계획 연결과 상태가 일치
- 사용자가 반복 입력·검색·조회에서 막히는 지점 기록
- 데이터 오류, 권한 오류, 성능 문제를 재현 가능한 형태로 기록
- 기존 ERP는 파일럿 기간 동안 원본 시스템으로 유지

## 진행 순서

1. 기존 ERP 이름과 export 형식 확인
2. 샘플 export 1개로 컬럼 매핑표 작성
3. 격리 PostgreSQL에서 dry-run import 및 오류 리포트 생성
4. 파일럿용 workspace에 승인된 테스트/실제 샘플 데이터 적재
5. 한 달 병행 사용 및 이슈 로그 작성
6. 수정 우선순위 결정
7. Edison 독립 QA와 CI 검증
8. 승인 후 고객사 납품 범위 확정

## 운영 안전 규칙

- Production DB에 원본 파일을 직접 import하지 않는다.
- Production schema/migration은 파일럿 데이터 준비와 분리한다.
- 삭제·대량 수정은 export 백업과 read-back/rollback 경로가 확인된 경우에만 수행한다.
- 기존 ERP 데이터가 고객 개인정보·거래기밀을 포함하면 채팅에 업로드하지 않고 로컬/승인된 저장소에서만 처리한다.

## 다음 입력 필요

- 기존 ERP 제품명/버전
- export 가능한 파일 형식(CSV/XLSX 등)
- 파일럿에 사용할 업무 기간
- 실제 데이터 대신 익명화 샘플을 사용할지 여부
