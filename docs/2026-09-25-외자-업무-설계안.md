# 외자(수입) 업무 설계안

## 확정된 업무 기준

- 월 처리량: 약 4~5건
- 통화: USD, JPY
- 원화 환산 기준일: 통관일(수입신고 수리일)
- 환율 입력: 사용자가 수입신고필증의 과세환율을 직접 입력
- 수입 부가세: 시스템에서 관리
- 수입 부가세 표시: 일반 매입 부가세와 분리한 별도 금액
- 과거 거래: 저장 당시 적용값을 보존하며 소급 재계산하지 않음

## 현재 구조 확인

- `Purchase`, `PurchaseRequest`, `Quotation`, `SalesPlan`에 `currency String?`가 이미 존재한다.
- 구매 입력은 통화 선택을 지원하지만 금액은 현재 공급가/부가세/합계의 단일 숫자 구조다.
- 구매 상태 화면은 현재 `내자`와 외자 통화를 분리하지만, 외자 금액을 원화로 계산하거나 표시하지 않는다.
- 수입 부가세·통관일·과세환율 전용 필드는 없다.
- 입고 전표와 재고 수량은 구매 라인 및 품목 코드에 연결되므로, 외자 필드는 구매 문서 범위에서 우선 검토한다.

## 제안 데이터 구조 (승인 전, 미적용)

`Purchase`와 필요 시 `PurchaseRequest`에 다음 nullable 필드를 추가한다.

- `customsDate DateTime?` — 통관일
- `customsExchangeRate Decimal/Float?` — 수입신고필증 과세환율. JPY는 **100엔당** 기준을 화면에 명시하고, `원화 환산액 = 외화 금액 × (100엔당 환율 ÷ 100)`으로 계산한다.
- `foreignAmount Decimal/Float?` — 원문 외화 금액
- `baseAmount Decimal/Float?` — 저장 당시 환율로 계산한 원화 금액
- `importVat Decimal/Float?` — 수입 부가세
- `importVatBaseAmount Decimal/Float?` — 수입 부가세 과세표준이 필요한 경우

금액은 구매 헤더 기준으로 저장하고, 필요하면 헤더 환율로 라인별 원화 금액을 계산한다. 외화 금액은 통화별 유효 소수 규칙을 적용하고, 원화 환산 결과는 원 단위 반올림한다. 수입 부가세 과세표준과 수입 부가세액은 신고필증 값을 직접 입력하며 기존 `vat`와 별도 표시한다. 기존 `amount`, `vat`, `total` 필드는 내자 호환을 위해 유지한다.

## UI 흐름 제안

1. 구매 등록 시 통화와 외화 금액 입력
2. 구매 확정 후 통관 단계에서 통관일, 과세환율, 과세표준, 수입 부가세 입력 표시
3. 원화 환산 금액을 계산해 미리보기
4. 저장 시 적용 환율·기준일·환산 금액을 함께 고정
5. 구매 상태/상세 화면에서 외화 금액과 원화 금액을 함께 표시
6. 입고·회계 연계 시 저장된 원화 금액을 사용하고 환율을 재조회하지 않음
7. 회계 화면에서 일반 매입 부가세와 수입 부가세를 별도 열·합계로 표시

## 구매 상태 화면 영향

현재 `app/purchases/status/page.tsx`의 필터에 외자 분기가 두 군데 있다(내자 조회 시 `currency !== "내자"` 제외, 외자 조회 시 `currency === "내자"` 제외). 외자 도입 시 이 필터 자체는 유지하되, 외자 결과에 통화·외화 금액·원화 환산액·통관일·수입 부가세를 표시하고 합계는 원화 환산액 기준으로 집계한다. 기존 내자 결과와 합계는 변경하지 않는다.

## 검증·보호 범위

- 외자 입력은 통관일·환율·외화 금액을 함께 검증한다.
- 환율 0 이하, 음수 금액, 통화-금액 불일치를 거부한다.
- workspace 권한과 VIEWER read-only 정책을 유지한다.
- 기존 내자 구매 생성·수정·입고·상태조회 회귀 테스트를 유지한다.
- 격리 PostgreSQL에서 외자 저장/read-back, 계산값 고정, workspace 분리, 권한 거부를 검증한다.
- Production schema migration과 배포는 별도 승인 전까지 진행하지 않는다.
- 운영 DB에는 `_prisma_migrations`가 없어 migration 적용 절차가 정리되지 않았다. 따라서 schema migration은 격리 PostgreSQL에서 먼저 검증하고, 운영 baseline/resolve 정책과 rollback/read-back 승인 전에는 Production에 적용하지 않는다.

## 미결정 사항

- Decimal 정밀도와 통화별 외화 소수점 규칙
- 과세표준·수입 부가세 입력의 필수 시점 및 수정 권한

이 문서는 설계안이며, 현재 Production DB·schema·환경변수에는 변경을 적용하지 않았다.
